Queue applications: lazy transfer and amortization

Session budget

0–10 recall · 10–25 baseline and choice · 25–45 primitive · 45–70 application and tests · 70–85 analysis/GATE · 85–90 exit note

One main task. Stop at 90 minutes and record partial work; optional extensions stay within the session.

Build the primitive

Implement lazy transfer only when the output stack is empty.

Apply it

Build a FIFO queue using two stacks and replay a long burst followed by alternating operations.

Explain why it works

Reading output top-to-bottom followed by input bottom-to-top gives FIFO order.

Analyze the costs

An individual dequeue can be O(n); total O(m) stack primitives over m operations, O(1) amortized per operation; O(n) stored items.

Test the boundaries

Transfer after peek, repeated peek, enqueue after partial drain, empty behavior.

GATE practice

Original potential/aggregate analysis MCQ; GATE DA 2026 Q39: compare total call count with maximum active depth.
