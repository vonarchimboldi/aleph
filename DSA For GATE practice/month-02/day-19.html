Killer application: sliding-window maximum

Session budget

0–10 recall · 10–25 baseline and choice · 25–45 primitive · 45–70 application and tests · 70–85 analysis/GATE · 85–90 exit note

One main task. Stop at 90 minutes and record partial work; optional extensions stay within the session.

Build the primitive

Build a deque of candidate indices; expire old indices and remove dominated values before appending.

Apply it

Return the maximum for every consecutive window of k values without rescanning the window.

Explain why it works

Candidate indices increase and their values decrease; all retained indices lie in the current window; the front is its maximum.

Analyze the costs

O(n) aggregate time: each index is appended once and removed at most once; O(k) auxiliary deque space, plus O(n-k+1) output.

Test the boundaries

k=1, k=n, equal values, increasing/decreasing sequences, maximum expiring; require 1<=k<=n.

GATE practice

Original NAT: count removals and distinguish amortized per-update work from worst-case work in a single update.
