Killer application: linked list + hashing for LRU

Session budget

0–10 recall · 10–25 baseline and choice · 25–45 primitive · 45–70 application and tests · 70–85 analysis/GATE · 85–90 exit note

One main task. Stop at 90 minutes and record partial work; optional extensions stay within the session.

Build the primitive

Using a provided sentinel-node scaffold, implement detach and append-to-recent; then combine them with a key-to-node map for get/put. Do not use OrderedDict.

Apply it

Implement bounded least-recently-used caching with positive capacity. The linked-list primitive lab and cache integration share this session’s coding budget; a working scaffold is allowed.

Explain why it works

Map keys equal list keys; each key has one node; list order is recency; size never exceeds capacity after an operation.

Analyze the costs

Expected O(1) get/put with hash-map assumptions and O(capacity) storage; worst-case hash lookup is not O(1).

Test the boundaries

Capacity one, update existing key, get changes recency, eviction, missing get.

GATE practice

Original cache-state trace; prove reciprocal links and map/list agreement, then explain expected O(1) get/put.
