Overview: hash tables

Session budget

0–10 recall · 10–25 representation · 25–55 core operations · 55–70 operation-log tests · 70–85 analysis/GATE · 85–90 exit note

One main task. Stop at 90 minutes and record partial work; optional extensions stay within the session.

Build the primitive

Implement an integer-key map with buckets: put/get/delete; force collisions using key modulo bucket count.

Apply it

Replay put/get/update/delete on a chained integer-key map, including collisions; preview membership and counting applications.

Explain why it works

Each key belongs to its hash bucket and appears at most once; updates replace its value.

Analyze the costs

Expected O(1) map operations with suitable hashing and bounded load; O(n) worst case; application expected O(n) time and O(n) space.

Test the boundaries

Colliding keys, duplicate update, absent deletion, negative integer keys under Python modulo.

GATE practice

Original collision and load-factor trace; distinguish expected lookup bounds from worst-case collisions.
