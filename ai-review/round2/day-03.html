AIR2-03-R0

From memory: whose preference does a MAX node represent, whose preference does a MIN node represent, and what comparison permits an alpha–beta cutoff?

Why can a smaller number be the correct choice?

Terminal numbers measure the outcome from MAX’s point of view. MAX chooses the largest available outcome; MIN chooses the smallest because the opponent is trying to reduce MAX’s outcome. Work upward from the leaves. A value at an internal node describes what can be forced under best play, not an average over possible moves.

Follow one complete example

A MAX root has MIN children L and R. L has leaves4,7 and R has leaves3,9. L returns4, R returns3, so the root chooses L and guarantees4. The tempting9 is unavailable against a MIN player who can choose3.

AIR2-03-W1

Change L to leaves2,8 and R to5,6. Which branch does MAX choose?

Worked check · open after your attempt

L returns2, R returns5; root chooses R with5.

Write MAX or MIN beside each node before comparing numbers.

What exactly have we learned when we stop early?

Alpha is a lower bound MAX already knows it can secure; beta is an upper bound MIN can impose. A cutoff is justified when the branch cannot beat an alternative already available. At a MIN node reached with alpha4, seeing a child value3 is enough: the node’s final minimum is at most3. We may not know its exact minimum, but MAX already has4 elsewhere. Never report an unexamined leaf’s value as if it had been calculated.

Follow one complete example

After L has returned4 in the first example, visit R. Its first leaf is3, so beta becomes3. Since beta≤alpha, skip9. R is known to be at most3; the complete tree happens to make it exactly3, but the cutoff itself only needs the bound.

AIR2-03-W2

If the unexamined leaf had been−20 instead of9, would the root decision change?

Worked check · open after your attempt

No. R would be−20, still worse for MAX than L=4. This is why an upper bound was enough.

How do the pieces fit together?

Every problem asks you to make an object you can reason with: a frontier, a game tree, a truth assignment, a path in a network or a probability table. The method then tells you which change is allowed. A final check asks whether the result answers the original question: cheapest route, forced conclusion or normalized probability. Learning the name of a method helps only when you can make and check those steps yourself.

Question and assumptions
  → representation: frontier / tree / assignment / network / factor
  → choose a rule and explain why it fits
  → carry out one justified step at a time
  → check cost, bound, truth or normalization
  → fresh problem without help
  → delayed recall and unfamiliar transfer
