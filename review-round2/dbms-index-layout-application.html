Indexes and B+ trees: access patterns, byte layout and splits

Round two · relative week 2 · unit 5 · application · 90-minute proposed session

An index helps a query find useful rows

A hash index organizes keys for exact matching. An ordered index, such as a B+ tree, also supports ranges of keys. Read the query’s conditions first. A condition Category=History asks for equality. Rating>4 asks for a range. Which index helps also depends on how many rows the condition keeps.

Internal nodes guide the search

A B+ tree has internal nodes that guide the search and leaves that locate the data. If an internal node points to four child ranges, three separator keys divide those ranges. In general, p child pointers go with p−1 keys. The letter p here counts pointers, not bytes.

Follow a complete example

Suppose one internal node has 128 bytes available. Each pointer uses 8 bytes and each separator key uses 12 bytes. We want the largest number of child pointers that fits.

First draw a smaller node. Four child ranges need three boundaries between them:

child 0 | key 1 | child 1 | key 2 | child 2 | key 3 | child 3

With p child pointers, there are p−1 keys. The pointers use 8p bytes. The keys use 12(p−1) bytes.

StepWhy it follows
8p + 12(p−1) ≤ 128The pointers and keys must fit in the node.
20p − 12 ≤ 128Expand the brackets and combine the p terms.
20p ≤ 140Add 12 to both sides.
p ≤ 7Divide by 20.

Seven pointers and six keys use 56+72=128 bytes. Eight pointers would need 64+84=148 bytes. The maximum is therefore seven child pointers. This maximum is called the internal node’s fanout.

R2-DBMS-05-A-Q1 · Start with one small step

An internal node has 4 child pointers. How many separator keys does it have? Explain with child ranges.

Worked check · open after attempting

Three separators divide the search space into four child ranges.

Count the bytes in the node you were asked about

Draw the pointer slots and key slots. Multiply the number of each by its byte size. Add any stated header. The total must fit the usable node size. Solve the resulting inequality and choose the largest integer that fits. Data-record pointers used in leaves do not belong in an internal-node calculation unless the question specifies that layout.

R2-DBMS-05-A-Q2 · Put the pieces together

Usable node bytes=256, child pointer=8 bytes, key=16 bytes, no header. Find maximum internal fanout.

Worked check · open after attempting

8p+16(p−1)≤256 implies 24p≤272, so p=11. Check p=12 exceeds capacity.

Insertion can split more than one level

First find the leaf where the new key belongs. If it overflows, split it according to the stated rule and add a separator to its parent. The parent can then overflow too. A split reaching the root creates a new root. Read the diagram’s separator convention because textbooks can use different boundary choices.

R2-DBMS-05-A-Q3 · Use the idea in an exam-style problem

A query filters Category='History' and Rating>4, then joins on IDs. Which filter can an ordinary hash index support directly, and which benefits from an ordered index? Explain without claiming a guaranteed speedup for every dataset.

Worked check · open after attempting

Hash supports equality on Category; an ordered B+ tree supports the Rating range. Benefit depends on selectivity, layout and the chosen plan; hash does not support ordered range access by itself.

How the ideas connect

Index choice follows the query; storage capacity follows a drawn layout; insertion follows the specified separator and split conventions.

Separate equality, range and join predicates. → Draw an internal node and account for every field. → Solve a byte inequality and floor at the end. → For insertion, follow the diagram’s separator convention and propagate overflow upward.
