Relational algebra and calculus: sets, witnesses and universality

Round two · relative week 2 · unit 2 · application · 90-minute proposed session

Read each operation as a question about rows

Selection keeps rows meeting a condition. Projection keeps chosen columns. In ordinary relational algebra, the result is a set, so duplicate projected rows appear only once. A natural join combines rows that agree on every column name the two inputs share. Write the input column names before computing a join.

Translate either and every carefully

Union collects values appearing in either set. Intersection collects values appearing in both. Set difference T−U keeps values in T that are missing from U. Therefore T−U=∅ means every value in T is present in U. This gives a way to express a requirement by searching for a counterexample to it.

Follow a complete example

To require every member of T to occur in A or B, test T−(A∪B)=∅. Using A∩B instead would demand membership in both sets, a stronger requirement.

R2-DBMS-02-A-Q1 · Start with one small step

T={1,2}, A={1}, B={2}. Evaluate T−(A∪B) and T−(A∩B). Which expresses membership in at least one set?

Worked check · open after attempting

The differences are ∅ and {1,2}, respectively. The union version expresses at least one.

An existence test needs one matching witness

In tuple relational calculus, a variable can stand for a candidate row. The symbol ∃ means there exists. To test an existence condition, look for at least one row satisfying it. Two matching witnesses still make the same condition true. They do not create two copies of the candidate in a set-valued result.

R2-DBMS-02-A-Q2 · Put the pieces together

X(P,Q)={(1,a),(1,b)} and Y(P,Q,R)={(1,a,9),(1,c,8)}. Compute X natural-join Y and then project P.

Worked check · open after attempting

Join result {(1,a,9)}, since both P and Q must match. Projection is {1}.

Division asks for complete coverage

Suppose Enrol records a student and a course. Dividing by a set of required courses asks which students appear with every required course. Choose a candidate student. Check each required course. One missing course rejects that student. This differs from asking whether the student took at least one required course.

R2-DBMS-02-A-Q3 · Use the idea in an exam-style problem

Enrol(student,course)={(A,x),(A,y),(B,x)} and Required(course)={x,y}. Who is returned by Enrol ÷ Required? State the quantifier explicitly.

Worked check · open after attempting

A only: for every required course there exists an enrolment pair for that student.

How the ideas connect

The central task is translating who qualifies into a set or logical condition while preserving the quantifiers and join attributes.

Read the required output attributes. → Translate every operator or quantifier into a condition on a candidate tuple. → Track intermediate relation schemas and duplicate elimination. → Use a witness or missing witness to accept or reject a candidate.

If a problem was difficult

  • Reading “all” as “some”
  • Joining only one of several shared columns
  • Counting witnesses as separate set-projection results
