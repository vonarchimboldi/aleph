Hashing: collision traces and expected-cost assumptions

Round two · relative week 1 · unit 4 · application · 90-minute proposed session

A hash chooses where to start

A hash table stores values in numbered positions. A hash function turns a key into a starting position. The expression k mod m means the remainder after dividing k by m. It always gives a position from 0 to m−1. For example, 18 mod 7 is 4 because 18=2×7+4.

Collisions need a rule

Two keys may have the same starting position. This is a collision. With linear probing, try that position first. If it is occupied, try the next position. Continue until an empty position appears. After the last position, return to position 0. Record each insertion before handling the next key.

Follow a complete example

With capacity 7 and h(k)=k mod 7, inserting 6,13,20 occupies slots 6,0,1. A search for 20 must follow that same probe sequence. Deleting 13 by simply making slot 0 empty would break a search that stops at the first empty slot.

R2-DSA-04-A-Q1 · Start with one small step

Compute 18 mod 7 and list the probe sequence starting there through four positions.

Worked check · open after attempting

4; positions 4,5,6,0.

A search must follow the same route

To find a key, repeat its insertion route. An empty position normally means the key is absent. Deletion therefore needs care. A tombstone is a marker saying a value was deleted but the search must continue. Replacing a deleted position with an ordinary empty position may hide a later key.

R2-DSA-04-A-Q2 · Put the pieces together

Capacity 7, h(k)=k mod 7, linear probing: insert 2,9,16,3. Give final slots.

Worked check · open after attempting

2→2,9→3,16→4,3→5.

An average bound needs assumptions

The load factor is the number of stored keys divided by the number of positions. A fuller table tends to require more probes. A bound stated under uniform hashing is an average under that model. It is not a guarantee for every arrangement, and it is not automatically a formula for every linear-probing implementation. Use the assumptions and bound supplied in the question.

R2-DSA-04-A-Q3 · Use the idea in an exam-style problem

At load α=0.8, an unsuccessful search has expected probe bound 1/(1−α). Explain why insertion of an absent key has the same search bound, and compute it.

Worked check · open after attempting

Insertion follows the unsuccessful-search probes to the first empty slot; the bound is 5 under the stated uniform-hashing model. It is not a worst-case guarantee.

How the ideas connect

A hash value is a starting location; the collision policy determines the actual position and search path.

Calculate the initial hash. → Probe consecutive occupied slots, wrapping modulo capacity. → Maintain the table after every insertion. → Connect insertion to unsuccessful lookup under the stated probabilistic model.
