Recursion: outputs, call counts and cost models

Round two · relative week 1 · unit 3 · application · 90-minute proposed session

A recursive call is another execution of the function

A recursive function calls itself on a smaller input. Each call has its own local input and must eventually reach a stopping case, called a base case. To understand a new function, start with a small input. Write which calls it makes and what each returns.

Decide what the question wants you to count

A function’s returned value, its total number of calls and its deepest chain of unfinished calls can all differ. The runtime stack holds unfinished calls. If a question asks for total activations, count every call, including calls that stop immediately. If it asks for maximum stack depth, count the longest chain that exists at one time.

Follow a complete example

If F(n) calls F(n−1) and F(n−2) for n>0 and stops for n≤0, total activations obey C(n)=1+C(n−1)+C(n−2), with C(0)=C(−1)=1. This differs from the returned value recurrence.

R2-DSA-03-A-Q1 · Start with one small step

For that function, list C(0), C(1), C(2), C(3), counting every invocation.

Worked check · open after attempting

1,3,5,9.

Write a recurrence that matches that count

A recurrence describes a quantity using the same quantity on smaller inputs. Suppose every non-base call makes two further calls. Its total-call count is one for the current call plus the call counts of both children. A binary-search call follows only one half, so its comparison count uses one smaller subproblem instead of two.

R2-DSA-03-A-Q2 · Put the pieces together

Binary search uses a three-way midpoint comparison, then chooses one half. With at most 15 elements, give its maximum number of midpoint comparisons on an unsuccessful search.

Worked check · open after attempting

4: a largest remaining-size sequence is 15→7→3→1→0. Count one comparison for each nonempty interval.

Average over the choices that are actually random

In quicksort on a random ordering of distinct keys, the first key can have any rank with equal probability. A rank with k smaller keys leaves subarrays of sizes k and n−1−k. Calculate the recursive work for each possible rank. Average those values, then add the work of partitioning. Assuming an equal split would replace the stated random process with a different one.

R2-DSA-03-A-Q3 · Use the idea in an exam-style problem

Quicksort receives a random permutation of n distinct keys and picks the first key as pivot. Write the expected-work recurrence assuming linear partition cost.

Worked check · open after attempting

T(n)=(1/n)Σ[k=0 to n−1](T(k)+T(n−1−k))+Θ(n). Uniform pivot rank, two recursive subarrays, and partition work must all be represented.

How the ideas connect

A recurrence must count the exact quantity asked for; output value, total calls, depth and expected work are different objects.

Name the counted primitive. → Expand a tiny call tree including base-case calls. → Separate sequential branches from simultaneous stack depth. → For expected cost, average over the stated random choice.

If a problem was difficult

  • Replacing an expected pivot split by a balanced split
  • Counting only non-base calls
  • Reporting depth when asked for total activations
