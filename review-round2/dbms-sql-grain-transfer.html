R2-DBMS-03-T-Q1 · delayed

Loan(branch,amount) rows are (X,40),(X,70),(Y,60),(Y,90). Return rows with amount greater than MAX(amount) over branch X. Is that subquery correlated?

Worked check · open after attempting

Only (Y,90). The threshold is 70 and is independent of the outer row, so the stated subquery is uncorrelated.

R2-DBMS-03-T-Q2 · transfer

Repeat the balance condition using 5,15,15,15,25. Which rows remain? Explain the role of equality.

Worked check · open after attempting

5 has greater 4,smaller 0 and remains. Each 15 has greater 1,smaller 1 and remains. 25 fails. Four rows remain; equal peers count on neither strict side.

Big picture

Correct SQL depends on the unit counted and the row scope of each expression, not just on recognizing COUNT or GROUP BY.

State the intended output grain: one row per what? → Materialize groups or matching rows on a tiny instance. → For a correlated subquery, fix one outer row before evaluating its inner query. → Test ties and duplicates explicitly.

Use the error to choose the next task

  • Grouping by a unique employee ID when a team size is wanted
  • Joining a row to itself instead of its whole group
  • Replacing a strict comparison by a rank formula that mishandles ties
