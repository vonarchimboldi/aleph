A dependency is a rule across all permitted rows

X→Y means that whenever two rows agree on attributes X, they must also agree on Y. A single agreeing pair does not prove the rule; a disagreeing pair can refute it. To compute X’s closure, start with X and repeatedly add the right side of any dependency whose left side is already present. Stop when no attribute can be added. X is a superkey if the closure contains the whole schema; it is a candidate key if no proper subset is also a superkey.

An attribute absent from every dependency’s right side must be supplied in each key, unless the full theory includes additional dependencies not listed. This is a useful search reduction, not a replacement for checking closure and minimality. We use exactly the stated dependencies and their logical consequences, and assume atomic attributes unless a question says otherwise.

Normal forms ask different questions

1NF is the atomic-domain starting convention used here. 2NF excludes a non-prime attribute’s dependency on a proper subset of a candidate key. Prime means belonging to some candidate key, not necessarily to the chosen primary key. 3NF requires, for every nontrivial dependency X→A in the closure of the dependency set, either X is a superkey or A is prime. BCNF removes the prime-attribute exception: every nontrivial determinant must be a superkey. A relation can therefore be in3NF but not BCNF.

Losslessness and dependency preservation concern a decomposition, not just each component’s normal form. A lossless decomposition reconstructs every permitted original relation by joining its projections without spurious rows. For a binary decomposition R₁,R₂ under functional dependencies, losslessness holds when the intersection functionally determines R₁ or R₂. Dependency preservation means the projected component constraints together imply the original dependencies, so they can be enforced without recombining relations. Neither property automatically gives the other.

Know the boundary of the first pass

Independent multivalued facts can create redundancy even in BCNF. For a Person–Hobby–Language table, if hobbies and languages vary independently for each person, a multivalued dependency can require all hobby/language combinations. A4NF decomposition separates PersonHobby and PersonLanguage. Independence is a semantic assumption; a small sample alone cannot establish it. Higher join-dependency/5NF practice belongs to the later-week extension when the selected syllabus interpretation or observed needs require it. Today’s diagnostic concentrates on FD closure through BCNF and binary decomposition.

Two worked examples

Prove a candidate key is minimal

R(A,B,C,D), F={A→B,B→C}. Find the candidate keys.

D never appears on a right side, so any key must contain D. No dependency produces A, so A is also mandatory. (AD)+ adds B then C, giving all four attributes. Removing A or D loses a required attribute, so AD is the sole candidate key. A+ is ABC, not the whole schema.

3NF does not imply BCNF

R(A,B,C), F={AB→C,C→B}. Analyze keys and the dependency C→B.

AB and AC are candidate keys. Thus every attribute is prime. C alone determines BC, not A, so it is not a superkey. C→B satisfies the3NF prime-right-side exception but violates BCNF. Decomposing into CB and AC is lossless because the intersection C determines CB, but AB→C is not preserved by the component FDs.

B04-Q1

A and C. A candidate key must be minimal. BCNF is stricter than3NF. A sample does not prove a universal dependency, and a lossless decomposition can fail dependency preservation.

First step: Separate relation properties from decomposition properties.. Diagnostic tag: fd-normal-form-logic. Likely trap: sufficient-versus-necessary.

B04-Q2

A, B and D. A+=ABC, and AD is the sole key because A,D cannot be derived. A→B is a partial dependency of non-prime B on the proper subset A of key AD, so2NF fails.

First step: Compute closure and minimality before classifying.. Diagnostic tag: closure-and-2nf. Likely trap: missing-key-attribute.

B04-Q3

A and D occur on no right side, so both are required. (AD)+ gives B,C, then E through CD→E. AD is minimal and every key must contain it, so it is the only candidate key.

First step: Find mandatory attributes, then iterate dependencies to a fixed point.. Diagnostic tag: candidate-key-search. Likely trap: stopping-closure-too-early.

B04-Q4

Yes to all three. Intersection A determines AB, so the decomposition is lossless. A→B is checked within AB, so preserved. In AB,A is a key; AC has no nontrivial projected FD, so both are BCNF.

First step: Test intersection closure and locate each original dependency.. Diagnostic tag: binary-decomposition. Likely trap: component-nf-versus-reconstruction.

B04-Q5

C determines CB, so the intersection criterion gives losslessness for original legal instances. For non-preservation, take CB={(c1,b1),(c2,b1)} and AC={(a1,c1),(a1,c2)}. They satisfy C→B in CB and no nontrivial FD in AC, but their join has the same AB=(a1,b1) with two C values. Local enforcement does not enforce AB→C.

First step: Distinguish reconstructing a legal instance from enforcing legality on arbitrary component updates.. Diagnostic tag: preservation-counterexample. Likely trap: lossless-implies-preserved.

Targeted repair

If a key is incomplete, list attributes never derivable from the given FDs. If preservation is confused with losslessness, build a two-row component counterexample.

A fresh check

Check after trying

The big picture

Text version of the mind map
  • Dependencies: Rules over all legal instances; Counterexample refutes; sample cannot prove.
  • Keys: Closure to a fixed point; Cover all attributes; test minimality.
  • Normal forms: Prime attribute exception in3NF; BCNF removes the exception.
  • Decomposition: Lossless reconstruction; Local enforcement is a separate property.
