Count physical units, not just records

A file stores records in pages or blocks. If records cannot straddle pages and headers are ignored, one page holds floor(page_bytes/record_bytes) records. The number of pages is the ceiling of record_count divided by that capacity. Taking one ceiling of total bytes divided by page size can be wrong because it lets fractions of records share unused space across pages.

A heap file supports simple insertion but does not sort its records by the searched field. A sorted file makes range scans natural but updates need care. An index is a separate access structure: it can reduce the pages searched while still requiring data-page reads for the matching records. Do not equate an index lookup with fetching the complete result for free.

Write the node’s contents before dividing

A B+ tree internal node with p child pointers has p−1 separator keys. With page size B, pointer size P and key size K, and no header, its layout requires pP+(p−1)K≤B. Solve for the largest integer p. A leaf has a different layout involving key/data-pointer entries and usually a next-leaf pointer; use the leaf’s stated convention instead of reusing the internal formula.

Separators guide search; record pointers are stored at leaves in the usual B+ model used here. Leaves are linked to support range scans. After a leaf split, the first key of the new right leaf is copied to the parent as a separator while remaining in the leaf. Internal-node splitting uses a different promotion convention. State capacity, insertion policy and split rule before tracing an update.

Match the index to the predicate

Hash indexes suit equality lookup but do not in general provide ordered range scanning. Ordered B+ indexes support equality and ranges. A composite ordered index on(A,B) orders first by A, then B inside each A region. A condition on A, or on A with a B range, can use contiguous key regions. A B-only predicate does not generally become one selective contiguous range; it may require scanning or implementation-specific techniques.

A clustered layout can place neighboring matching records on fewer data pages than an unclustered layout. Count cached root pages, index pages and data pages using the assumptions supplied. Bitmap indexes can help low-cardinality analytical attributes, but their benefit depends on workload and update behavior; “one index is always best” is not a valid universal rule.

Two worked examples

Internal fanout is an inequality

An internal page has1000 bytes, 8-byte child pointers, 8-byte keys and no header. Find maximum p.

The layout is8p+8(p−1)≤1000, or16p≤1008. Thus p≤63 and the maximum is63 pointers, with62 keys. Ignoring the extra pointer would change the answer.

Leaf split needs a convention

A leaf allows3 keys and currently has[5,9,13]. Insert11. Split four sorted entries evenly into two leaves, copy the right minimum upward.

The entries are[5,9,11,13]. Leaves become[5,9] and[11,13]. The parent receives separator11;11 also remains in the right leaf. This is leaf-copy behavior, not removing11 from the leaf as in an internal promotion.

Targeted repair

For a fanout miss, draw the alternating pointer/key layout. For file size, compute records/page first. For I/O, list each distinct uncached page read.

Text version of the mind map
  • Storage: Unspanned records and block capacity; Floor capacity; ceiling page count.
  • Layout: Internal pointers versus leaf entries; Include headers/sibling pointers if stated.
  • Access: Equality versus ordered range; Composite leading-column order.
  • Cost: Index pages and data pages; Caching changes the count.
