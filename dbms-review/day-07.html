Ask what information should survive

A transformation changes how data is represented. Scaling preserves numeric ordering under a positive affine map; discretization replaces detailed values with bins; sampling keeps a selected subset or draws; compression changes storage representation and may or may not preserve exact recoverability. These operations solve different problems. “Normalize” is overloaded: numeric normalization rescales values; relational normalization decomposes schemas using dependencies. Neither is a substitute for the other.

Scaling needs reference statistics

Min–max scaling to[0,1] uses z=(x−min)/(max−min), assuming max>min. Z-score standardization uses z=(x−mean)/standard_deviation, assuming a positive standard deviation. State whether supplied statistics are population or sample estimates if computing them; today’s questions supply the standard deviation directly. An input outside the reference min/max can transform outside[0,1]. That is not an arithmetic contradiction.

For prediction, fit scaling parameters using the training data, then reuse them on later data. Recomputing them using the test set changes the mapping and can leak information. If an attribute is constant, the standard formulas divide by zero; an explicit constant-feature policy is needed.

Bins and samples need boundaries and a model

Equal-width discretization divides a numeric interval into intervals of equal numeric length. Equal-frequency discretization aims for similar record counts, which need not produce equal widths; ties require a stated policy. Always specify which bin contains a boundary value. Replacing a number by its bin usually loses its exact original value.

Simple random sampling, stratified sampling and sampling with replacement use different probability models. Without replacement, a record can appear at most once in the selected sample. With replacement, repeated records are possible. Stratification samples within declared groups; it does not by itself make a combined unweighted estimate correct if sampling fractions differ. Preserve weights when the question requires a population estimate.

Compression requires a decoding story

Lossless compression permits exact reconstruction; lossy methods trade information for a reduced representation. Run-length encoding stores consecutive runs as(symbol,count), so it helps long runs and can expand alternating data. Dictionary and delta encodings exploit other patterns; a storage saving cannot be asserted without specifying the encoding sizes and overhead. A sample or a bin label is not generally an exact substitute for the full original data.

This final day also consolidates the full section: a well-normalized schema says little about whether a feature is standardized; a valid SQL result says little about whether its numerical average was reaggregated correctly. Translate the intended question first.

Two worked examples

Use the right statistics

An attribute has reference min10,max50,mean30,std10. Transform x=40 by min–max and z-score methods.

Min–max gives(40−10)/(50−10)=0.75. Z-score gives(40−30)/10=1. The outputs differ because the first measures position in a reference range and the second measures standard-deviation displacement from a mean.

Compression can expand

Encode AAABBCC using one byte per symbol and one byte per run count, ignoring headers. Compare ABAB.

AAABBCC has7 input bytes and3 runs, so encoding takes6 bytes. ABAB has4 bytes and4 runs, so its encoding takes8 bytes. The method is lossless in both cases; compressibility depends on the data pattern and the specified representation.

Targeted repair

For scaling errors, write the formula name and denominator before substituting. For binning, mark each endpoint. For compression, count encoded units before claiming a saving.

  • Purpose: Scale; bin; sample; encode; Do not confuse feature and schema normalization.
