The split alone does not determine the cost

A recursive algorithm does work at the current problem and delegates smaller problems to recursive calls. Count both. Mergesort splits into two roughly equal halves, sorts them and merges in linear work. Its recurrence is T(n)=2T(n/2)+Θ(n), giving Θ(n log n). There are logarithmically many levels and linear total merge work per level. Auxiliary-array mergesort typically uses Θ(n) extra storage, not in-place constant space.

The merge invariant is that the output contains the smallest already-consumed items from the two sorted inputs, in order. Choose the left item on equal keys to preserve cross-half stability. The remaining tail can be copied when one side empties. Two input arrays of lengths p,q require at most p+q−1 key comparisons if both are nonempty, because after that only one tail remains.

Quicksort makes a different promise

Partitioning places a pivot so that one side has the prescribed smaller/equal relation and the other has the complementary larger relation. The sides are not yet sorted. With a balanced split, recursion costs Θ(n log n); repeatedly choosing an extreme pivot can yield T(n)=T(n−1)+Θ(n), or Θ(n²). Randomization gives expected balance under its model, not a worst-case guarantee for every run.

For reproducible traces here, Lomuto partition uses the last item as pivot, scans the earlier positions left to right, and moves entries ≤pivot to the left region. Finally it swaps the pivot after that region. Equal keys can all go to the same side; a three-way partition is a different implementation.

A heap is a selection tool

A binary min-heap is a complete binary tree whose parent key is at most each child’s key. In a zero-based array, children of i are 2i+1 and 2i+2 when those indices exist. Extracting the minimum replaces the root with the last item and sifts downward, costing O(log n). Arbitrary membership search is not generally O(log n), because neither child region rules out the key the way a BST does.

Bottom-up heap construction is Θ(n): many nodes are near the leaves and move little. Bounding every sift by log n gives a valid but loose O(n log n) upper bound, not the tight construction cost. Heaps and heapsort are supporting tools here; the DA syllabus explicitly names mergesort/quicksort and trees, rather than listing every sorting technique in Skiena.

Lomuto partition: the final item is the pivot

def partition(a):
    pivot = a[-1]  # precondition: a is nonempty
    boundary = 0
    for j in range(len(a) - 1):
        if a[j] <= pivot:
            a[boundary], a[j] = a[j], a[boundary]
            boundary += 1
    a[boundary], a[-1] = a[-1], a[boundary]
    return boundary  # not a complete sorting algorithm

Scan4:leave it; scan2:swap into the left region to get[2,4,5,1,3]; scan5:leave it; scan1:move it left to get[2,1,5,4,3]. Place pivot after the ≤ region, giving[2,1,3,4,5], pivot index2. The left side[2,1] still needs sorting.

The big picture

Explain partition/merge invariants and choose a recurrence from the code’s work. Explain the result through a representation, an invariant, and a cost model. A correct final array or number is incomplete when the question asks why the steps work.

Text version of the mind map
  • Decompose: Balanced halves or pivot regions; Write actual recursive sizes.
  • Combine: Merge maintains sorted output; Partition does not finish sorting.
  • Analyze: Per-level work; worst/expected; Trace comparisons separately.
  • Priority queue: Heap root is extremum; Heap property is weaker than sorting.
