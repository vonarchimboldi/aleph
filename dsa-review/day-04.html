A sort has more than one observable property

Sorting puts records in nondecreasing key order. If records share a key, a stable sort keeps their original relative order. Stability concerns tagged records, not just identical numbers. Also distinguish in-place rearrangement from auxiliary copying, and best-case behavior from worst-case behavior.

Selection sort fixes the next output position by scanning the unsorted suffix for its smallest item, then swapping it into place. With a full suffix scan at each step, the number of key comparisons is n(n−1)/2, even if the input is already sorted. It performs at most n−1 nontrivial swaps. A long swap can move one equal-key record past another, so the usual swap implementation is not stable.

Insertion sort keeps a sorted prefix. It takes the next item, shifts larger prefix items right, then places the item in the gap. Comparing with “greater than,” rather than “greater than or equal,” keeps equal keys in their original order. On already-sorted input, it needs just one failed greater-than key comparison per new item. On reverse-sorted distinct input, it shifts one item for every inversion, giving quadratic work.

Bubble sort compares adjacent items left to right and swaps an inverted pair. A full pass puts the largest remaining item at the right boundary. With an early-exit flag, a pass with no swaps proves the current array is sorted. Without that flag, the same input may still run all fixed passes. When exact counts matter, write whether pass lengths shrink and whether comparisons stop early.

Do not infer implementation from a name

Two functions called bubble_sort may have different best-case comparison counts. In every trace below, bubble passes go left to right through the unsorted prefix, the right boundary shrinks by one per pass, and a zero-swap pass stops the algorithm. Selection scans the whole suffix. Insertion shifts only strictly larger keys. These conventions make answers reproducible.

Insertion sort: strictly greater keys move right

def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

Trace the code on a small example. Identify which stored state expresses the invariant and which line guarantees progress. The diagnostic may ask a nearby variant; read its exact convention again.

Tagged duplicates expose instability

Selection-sort [2a,2b,1] by the numeric part.

The first minimum is1 at the end, swapped with2a, yielding[1,2b,2a]. The order of equal-key records reversed, so this implementation is not stable. Insertion using strict > would shift both2s right without changing their order.

A fresh check

Why does changing insertion’s shift condition from > to ≥ threaten stability?

Fresh-check answer — open after trying

It shifts equal keys too, so a later equal record can be inserted before earlier equal records.

Text version of the mind map
  • Goal: Order by key; Keep record identity for ties.
  • Invariant: Selection: fixed prefix; Insertion: sorted prefix.
  • Implementation: Bubble direction and early exit; Strict comparison controls stability.
  • Evidence: Trace; count; counterexample; Best case differs from worst case.
