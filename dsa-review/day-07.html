What is a shortest path minimizing?

For unweighted graphs, path length counts edges, so BFS layers solve the problem. For weighted graphs, a two-edge route can cost less than a one-edge route. The question must state the edge weights and whether negative values are allowed. Confusing edge count with total weight selects the wrong algorithm before any arithmetic begins.

Relaxing an edge u→v of weight w means checking whether a known route to u followed by this edge improves the current distance estimate for v: d[v]=min(d[v],d[u]+w). A distance estimate represents an actual discovered route and is an upper bound on the best route when finite. Initially d[source]=0 and others are infinity.

Dijkstra’s algorithm repeatedly finalizes the unprocessed vertex with smallest tentative distance, then relaxes its outgoing edges. Nonnegative weights make that finalization safe: reaching a new unprocessed region cannot create a cheaper path back through a negative last step. A later better route is impossible under the theorem’s assumptions. With negative edges, that argument can fail even without a negative cycle.

For a standard adjacency-list implementation with a suitable binary heap, the cost is O((V+E)log V); a simple array minimum selection gives O(V²+E). State the implementation. Bellman–Ford repeatedly relaxes all edges and supports negative weights, with O(VE) worst-case work; a reachable negative cycle can make some distances unbounded below. These details are selected support for the syllabus’s general “shortest path” wording, not a claim that every algorithm named here is separately enumerated there.

Bring the week back together

Graphs expose why data structures and invariants belong together. BFS needs FIFO order; Dijkstra needs a minimum-priority choice; a dictionary can map vertex labels to stored state. A heap’s role is minimum selection, not binary search. An adjacency representation changes which operations cost time. The same analysis habits from Day1 now explain whole algorithms.

Dijkstra: nonnegative weights justify finalization

from heapq import heappush, heappop

def dijkstra(adj, source):
    # adj[u] contains (neighbor, nonnegative weight).
    distance = {source: 0}
    final = set()
    heap = [(0, source)]
    while heap:
        cost, u = heappop(heap)
        if u in final:
            continue
        final.add(u)
        for v, weight in adj[u]:
            if v not in final:
                candidate = cost + weight
                if candidate < distance.get(v, float('inf')):
                    distance[v] = candidate
                    heappush(heap, (candidate, v))
    return distance

Trace the code on a small example. Identify which stored state expresses the invariant and which line guarantees progress. The diagnostic may ask a nearby variant; read its exact convention again.

Two worked examples

A direct edge can be the wrong choice

Directed edges S→A:4,S→B:1,B→A:2,A→T:1,B→T:7. Run Dijkstra from S.

Start dS=0. Finalize S:update A=4,B=1. Finalize B:update A=3,T=8. Finalize A:update T=4. Finalize T. Final distances S0,B1,A3,T4; path to T is S→B→A→T. The direct-to-A route was not the cheapest.

Why a negative edge breaks finalization

Directed edges S→A:2,S→B:5,B→A:−10. What goes wrong with ordinary finalized-once Dijkstra?

It finalizes A at2 before B, but the route through B later costs5−10=−5. A was not final after all. There is no cycle in this graph, so absence of negative cycles alone does not justify Dijkstra. Bellman–Ford can handle these finite negative edges.

With S→A weight10,S→B weight1,B→A weight1, does BFS minimize total weight?

Fresh-check answer — open after trying

No. The one-edge route costs10, while the two-edge route costs2. BFS minimizes edges, not arbitrary positive weights.
