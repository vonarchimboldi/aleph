One dictionary interface, different machinery

A dictionary associates a key with a value. We may need lookup, insertion, deletion, sorted iteration, predecessor or successor. A hash table and a binary search tree can implement some of the same interface, but their tradeoffs differ. Start with the requested operations rather than choosing the structure by name.

A hash function maps a key to a bucket or initial position. Different keys can collide. Chaining stores several entries in a bucket; open addressing probes other table positions. A low load factor helps but does not make collisions impossible. Expected constant-time operations need assumptions about hashing and load. Worst-case search can still be linear.

With linear probing, a lookup follows the same probe sequence as insertion and stops only at a never-used empty slot or a matching key. Deleting by making an occupied slot look never-used can break later searches. A tombstone preserves the probe chain. During insertion, a tombstone can be reused, but a dictionary must still avoid creating a second entry for a key already later in the chain.

A BST preserves order rather than buckets

In a binary search tree with distinct keys, every key in a node’s left subtree is smaller and every key in its right subtree is larger. The condition concerns the whole subtrees, not only immediate children. Inorder traversal returns sorted keys because it visits left subtree, node, right subtree. Search/insertion take O(h), where h is tree height. Balanced height is O(log n); inserting sorted keys into an ordinary unbalanced BST can create height n−1.

For deletion, a leaf is removed directly; a node with one child is replaced by that child. With two children, use the smallest key in the right subtree (or the largest in the left), then remove that replacement node from its old position. State the duplicate-key policy before tracing insertions; these notes use distinct keys or value replacement on repeated keys.

Heaps also use trees, but their parent/child ordering does not make inorder traversal sorted and does not support arbitrary membership search in logarithmic time. Day 5 uses heaps for repeated minimum extraction, not as an ordered dictionary.

BST search uses the whole-tree ordering invariant

def contains(root, key):
    node = root
    while node is not None:
        if key == node.key:
            return True
        if key < node.key:
            node = node.left
        else:
            node = node.right
    return False

Trace the code on a small example. Identify which stored state expresses the invariant and which line guarantees progress. The diagnostic may ask a nearby variant; read its exact convention again.

Two worked examples

A collision trace

Table indices 0…6, h(k)=k mod7, linear probing. Insert 10,17,24.

All initially hash to slot 3. They occupy 3,4,5. Deleting 17 must leave a tombstone at 4, otherwise searching for 24 would stop there and falsely report absence.

Order constrains a whole subtree

Insert 5,2,8,1,4,7 into an empty BST.

Root 5 has left 2 and right 8; node2 has children1 and4; node8 has left7. Inorder gives1,2,4,5,7,8. Deleting root5 using its inorder successor replaces it with7 and removes7 from below8.

D03-Q1

A and D. Balanced height gives logarithmic BST operations. Tombstones keep searches from ending too early. Collisions can occur even with a low load factor; expected and worst-case costs differ.

D03-Q4

Preorder:4,2,1,3,6,5,7. Inorder:1,2,3,4,5,6,7. The distinction is whether the node is visited before or between its subtree visits.

Diagnostic tag: tree-traversal. Likely trap: visit-position. First step: Write traversal rules before expanding subtrees..

D03-Q5

Hashing organizes by bucket rather than key order, so minimum/range queries may need scans. A min-heap supports repeated minimum extraction; a balanced BST supports ordered range traversal and updates. Choice depends on whether both capabilities must share one representation.

Diagnostic tag: representation-choice. Likely trap: lookup-is-not-order. First step: Name the required operations and their ordering information..

Targeted repair

For a hashing miss, trace probe positions including tombstones. For a BST miss, check the entire ancestor bounds rather than parent-child pairs.

The big picture

Distinguish expected costs from guarantees, and membership lookup from ordered queries. Explain the result through a representation, an invariant, and a cost model. A correct final array or number is incomplete when the question asks why the steps work.
