First decide what an edge means

A graph models objects as vertices and relationships as edges. Specify directed or undirected, weighted or unweighted, and whether self-loops or parallel edges are allowed. Replacing an undirected road with a single directed arc changes reachability. A representation is part of the problem definition, not just a storage detail.

An adjacency matrix needs Θ(V²) storage and supports constant-time edge-existence lookup. An adjacency list uses Θ(V+E) storage and enumerates a vertex’s neighbors in time proportional to its degree. For an undirected graph, each ordinary edge appears twice in the lists. The complexity of an algorithm depends on the representation: scanning each matrix row during traversal costs Θ(V²), not Θ(V+E) on a sparse graph.

BFS organizes reachable vertices by distance

Breadth-first search uses a queue. Mark a vertex when you enqueue it, not after processing it, so two parents do not enqueue the same child twice. Set its distance to its parent’s distance plus one. All vertices at distance d are discovered before vertices at distance d+1, which gives shortest path lengths in an unweighted graph. The chosen parent among tied shortest paths depends on neighbor order.

Depth-first search follows a branch until it cannot continue, then backtracks. A recursive DFS uses the call stack. To state a deterministic trace, give a start vertex and an order for neighbors; below we use alphabetical order. An iterative stack implementation may need neighbors pushed in reverse order to match recursive visitation. DFS establishes reachability, but the first route it discovers is not generally a shortest route.

With adjacency lists and a visited structure, a full traversal over all vertices and edges takes O(V+E). A single source only visits its reachable portion; to count connected components of an undirected graph, start another traversal at each still-unvisited vertex. In a directed graph, this outer-loop count does not by itself count strongly connected components. That needs a separate algorithm.

BFS: mark by assigning distance before enqueue

from collections import deque

def bfs_distances(adj, source):
    distance = {source: 0}
    waiting = deque([source])
    while waiting:
        u = waiting.popleft()
        for v in sorted(adj[u]):
            if v not in distance:
                distance[v] = distance[u] + 1
                waiting.append(v)
    return distance  # unreachable vertices are absent

Trace the code on a small example. Identify which stored state expresses the invariant and which line guarantees progress. The diagnostic may ask a nearby variant; read its exact convention again.

Two worked examples

Same graph, different exploration discipline

Undirected edges A–B,A–C,B–D,C–D,D–E. Start A, alphabetical neighbors. Compare BFS with recursive DFS.

BFS order:A,B,C,D,E; distances0,1,1,2,3. Recursive DFS order:A,B,D,C,E. DFS follows D to C before returning and visiting E. Both reach all vertices; their parent trees and visit order differ.

A duplicate enqueue is a state bug

A connects to B,C and both connect to D. Why mark D when it is enqueued?

After processing B, D is already discovered and waiting. Processing C must not enqueue D again. Marking on enqueue records that waiting state. Marking only when dequeued permits duplicate entries and complicates distance/parent accounting.

D06-Q1

A and C. Lists scale with vertices plus stored edges. BFS supplies shortest edge counts in an unweighted graph. Matrices take quadratic storage, and DFS need not discover a shortest path first.

Diagnostic tag: graph-model-cost. Likely trap: representation-independent-cost. First step: State the representation and the path metric..

D06-Q2

A and D. Each vertex is enqueued at most once. Starting BFS at every unvisited vertex counts connected components for undirected graphs. It does not count strongly connected components of arbitrary digraphs, and list ordering can select different tied parents.

Diagnostic tag: discovery-and-components. Likely trap: undirected-versus-directed. First step: Separate discovered from processed and identify graph direction..

A fresh check

Can two valid BFS runs have different parents but identical distances?

Fresh-check answer — open after trying

Yes. When two shortest paths tie, neighbor order can select a different discovering parent; shortest edge counts remain the same.

The big picture

Make graph traces deterministic and distinguish reachability, traversal order and unweighted distance. Explain the result through a representation, an invariant, and a cost model. A correct final array or number is incomplete when the question asks why the steps work.
