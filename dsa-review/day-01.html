Before choosing an algorithm, define the job

An algorithm is a sequence of permitted steps with a specified result. “Find the target” is incomplete: should we return any occurrence, the first occurrence, or an insertion position? Must the input be sorted? An algorithm can be fast and still answer the wrong question. Write the input, output, precondition and edge cases before counting work.

A loop invariant states what remains true before each iteration. It connects the steps to the intended answer. In linear search, every earlier position has already been checked and does not contain the target. In binary search, the remaining interval contains every candidate not yet ruled out. The update must preserve that claim and reduce the interval so the algorithm terminates.

Count the operations that actually execute

For a nested loop, count the inner executions for each outer value and then add. A triangular loop executes 1+2+…+n=n(n+1)/2 times, which is Θ(n²). An outer loop does not automatically multiply by n if its inner limit depends on the outer index. Doubling a counter until it reaches n takes Θ(log n) iterations, not Θ(n).

Big-O is an eventual upper bound; Θ states matching upper and lower growth bounds. Neither notation is an exact operation count. Also say which input case you mean: linear search can succeed on the first comparison, but its worst case checks all n positions. A Python slice usually copies elements, so apparently small code can allocate linear extra space.

A precise binary-search variant

For lower_bound, we want the first index whose value is at least the target, or n if no such index exists. Use a half-open interval [lo,hi), initially [0,n). Values before lo are below target; values from hi onward are at least target. With mid=(lo+hi)//2, move lo to mid+1 when a[mid]<target; otherwise move hi to mid. Equality stays on the left-search side because we need the first acceptable position. The interval gets shorter even for length one.

For [1,3,3,7], target 3, start (lo,hi)=(0,4). Mid=2 holds 3, so hi=2. Mid=1 holds 3, so hi=1. Mid=0 holds 1, so lo=1. Now lo=hi=1: the first 3 is at index 1. The result n on an absent-too-large target is a valid insertion position, not an array element to dereference.

Lower bound: the interval [lo,hi) contains unresolved positions

def lower_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

Trace the code on a small example. Identify which stored state expresses the invariant and which line guarantees progress. The diagnostic may ask a nearby variant; read its exact convention again.

Two worked examples

Trace first, then generalize

For n=4, execute: for i in range(n): for j in range(i+1): count += 1.

The inner execution counts are 1,2,3,4, totaling 10. For general n they sum to n(n+1)/2, giving Θ(n²). The sum is an exact count; Θ(n²) records its growth.

A shrinking interval

Why does lo=mid fail as the update in the less-than branch of half-open lower_bound?

With lo=0, hi=1, mid=0 and a[0] below target, lo=mid leaves (0,1) unchanged forever. Using mid+1 removes the tested failing position and guarantees progress. This is a termination error, not just a wrong final index.

D01-Q1

A and C. Binary search uses sorted order to discard candidates; an upper bound need not be tight. The triangular count is quadratic, and copying k Python list entries needs Θ(k) space.

Diagnostic tag: bounds-versus-count. Likely trap: loose-upper-bound. First step: Separate the exact count, the input precondition, and the bound..

D01-Q2

A, B and D. Targets 4,5,10 give indices 1,3,4. An empty array starts with lo=hi=0 and never enters the loop.

Diagnostic tag: binary-boundaries. Likely trap: duplicate-and-sentinel. First step: Trace the half-open interval; distinguish a returned insertion index from an existing element..

D01-Q3

For n=8: j is 1,2,4 at loop entry, so 3 iterations. For positive n the count is ceil(log₂n), with zero when n=1. Growth is Θ(log n) for growing n.

Diagnostic tag: doubling-loop. Likely trap: value-versus-iteration. First step: List j values at loop entry..

D01-Q4

a and b both reference [1,2,3]. c is a separate shallow list and becomes [9,2]. Appending changes the aliased list; assigning c[0] changes only the copy.

Diagnostic tag: python-aliasing. Likely trap: alias-versus-copy. First step: Draw list objects separately from variable names..

D01-Q5

First-position success uses 1 comparison; absence uses n. Average cost requires a probability model over targets/positions or cases; it is not fixed by the code alone.

Diagnostic tag: case-analysis. Likely trap: average-without-model. First step: Identify which execution path is being counted..

The big picture

Separate exact counts from growth bounds, and explain why a search interval shrinks. Explain the result through a representation, an invariant, and a cost model. A correct final array or number is incomplete when the question asks why the steps work.

Text version of the mind map
  • Specify: Input/output and preconditions; Any match versus first match.
  • Execute: Trace actual Python state; Aliases, copies and boundaries.
  • Explain: Invariant plus progress; Preserve candidates; shrink interval.
  • Analyze: Exact count before Θ; State best/worst/expected case.
