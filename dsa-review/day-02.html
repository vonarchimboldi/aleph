Operations determine the useful representation

An array stores entries at indexed positions, making random access constant time in the usual RAM model. Inserting in the middle generally shifts later entries and costs linear time. A linked list stores nodes with links. Finding the kth node takes a walk; inserting after an already-known node changes a constant number of links. “Linked-list insertion is O(1)” hides the condition that the insertion location has already been found.

To insert z between p and its successor, first set z.next=p.next, then p.next=z. Reversing those assignments makes z.next point to z and loses the old successor. A temporary reference can be the difference between preserving a whole structure and disconnecting it. For deletion, update the predecessor link; deleting the head requires updating the head variable itself.

Stack and queue describe access discipline

A stack removes the most recently added item: last in, first out. A queue removes the earliest still-waiting item: first in, first out. A Python list supports append/pop at its right end for a stack, but pop(0) shifts the rest and costs Θ(n). A deque supports efficient operations at both ends. The abstract queue rule does not guarantee that every implementation has constant-time dequeue.

A circular queue reuses an array. Let head be the next removal index and size the number of items. With capacity C, the next insertion index is (head+size) mod C; after removal, head=(head+1) mod C and size decreases. Using size distinguishes full from empty even when indices wrap around. State what happens on overflow or underflow rather than silently overwriting data.

An invariant can describe unfinished work

For a balanced-bracket scan, the stack contains unmatched opening brackets from the prefix already read, in their order of nesting. An opening bracket pushes. A closing bracket must match the current top; an empty stack or mismatched type fails immediately. Finishing with a nonempty stack also fails. This invariant explains both correctness and which error a trace reveals.

Preserve the successor before changing the predecessor

# p has a successor; z is a new node.
z.next = p.next
p.next = z

# A FIFO queue without list.pop(0):
from collections import deque
waiting = deque([2, 5])
first = waiting.popleft()  # 2
waiting.append(7)         # front-to-back: 5, 7

Trace the code on a small example. Identify which stored state expresses the invariant and which line guarantees progress. The diagnostic may ask a nearby variant; read its exact convention again.

Two worked examples

Links have an order of assignment

Insert node 5 after node 3 in 1→3→8.

Keep the old successor 8 available. Set 5.next to 8, then 3.next to 5. The result is 1→3→5→8. Setting 3.next first and then copying it into 5.next would create a self-loop at 5.

Circular does not mean reordered

Capacity 4, head=3, size=2: which slots are occupied, and where is the next insertion?

The queue occupies slots 3 and 0 in that removal order. The next insertion goes at (3+2) mod4=1. Removing once makes head=0,size=1. The logical order follows head and size, not increasing physical indices.

Targeted repair

For a pointer error, draw every reference after each line. For queue errors, write head and size after every operation. Do not repair only the final output.

The big picture

Choose a representation from its operations and protect its state invariant. Explain the result through a representation, an invariant, and a cost model. A correct final array or number is incomplete when the question asks why the steps work.

Text version of the mind map
  • Representation: Array: indices; list: links; Known position versus search.
  • Discipline: Stack LIFO; queue FIFO; Abstract rule versus implementation.
  • State invariant: Unmatched openings or queue interval; Head, size and wrap-around.
  • Boundary cases: Empty/head/tail/full; Preserve links before updating.
